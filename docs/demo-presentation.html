CiteSight

Academic integrity · citation verification

Verify the citations in student work — before you sign off on the grade.

Demo · Desktop app · v0.8.28

Welcome. This is CiteSight, a tool for marking: it checks that the references and in-text citations in a student assignment are real, correctly cited, and actually used. Today we'll download the desktop app, point it at a folder of submissions, and read the results. Timing: ~15 minutes plus questions.

Marking question: are those references real?

  • Fabricated references — plausible-looking, don't exist
  • Mismatched — the cited claim isn't what the source says
  • Orphans — in-text citations with no bibliography entry
  • Dead / bot-blocked URLs and broken DOIs
  • Formatting drift across APA, MLA, Chicago

Checking one paper by hand is tedious.
Checking a tutorial set of 30 is worse.

CiteSight does the mechanical pass so your time goes to judgement calls.

It verifies existence and metadata — you still decide whether the source supports the claim.

Frame it as the mechanical layer of marking references: does each entry exist, is it cited in the text, does the formatting follow the required style? Emphasise the division of labour: CiteSight flags; the tutor judges. It is evidence, not a verdict.

How a reference gets verified

  1. Parse — pull authors, title, year, journal, DOI, URL from the entry
  2. Validate format — against the selected style
  3. Verify existence — cascade of free databases:
    • DOI? → Crossref → then title + author search → Semantic Scholar → OpenAlex
    • Has a URL? → HTTP status check (+ optional screenshot)
  4. Cross-reference — match bibliography ↔ in-text citations, flag orphans
  5. Score — confidence 0–1 from metadata match quality

A DOI on a paywalled publisher page is reported as blocked, not dead — the DOI itself still resolves.

Keep this brief in the live demo — it's the "why results look the way they do" slide. The confidence score reflects how well the parsed entry matched a real record: exact DOI match scores high; a fuzzy title-only match scores lower and lands in "needs review".

Reading the results — Overview

Each paper gets a dashboard with an overall verdict:

All clear   Caution   Issues

  • A proportion bar: verified / to-check / unverifiable
  • A "Things to check" priority list — ranked, with the evidence attached
  • Counts: N to review · N not found · N orphan citations

Start at the top of the priority list; work down until you're comfortable.

The verdict pill is the triage signal: green papers can be skimmed, amber and rose deserve the priority list. "All clear" still means *formatting and existence* check out — not that every claim is properly supported.

Reading the results — References tab

  • Every reference, one row, with status: Verified Likely valid Needs review Not found Unverified Dismissed
  • Confidence meter (0–1) per row — how well the entry matched a real record
  • Expand a row to see: what was cited vs. what the matched record holds, format issues, flags
  • Page snapshot — screenshot of any cited web page; shown in-app and embedded as a thumbnail in the PDF export

Row actions: Open DOI · Open cited URL · Search Scholar · Search web · Re-check · Dismiss

Demo the expand: show the cited-vs-matched comparison — this is where mismatches jump out (right title, wrong year; real paper, real authors, but not the one the student described). The page snapshot is handy evidence for a chat with the student: what the cited page looked like when you marked it.

Reading the results — Cross-refs tab

Two mismatch lists

  • Unmatched bibliography entries — listed but never cited in the text
  • Orphaned in-text citations — cited but missing from the bibliography

Both are classic signs of assembled-at-the-deadline referencing.

One-click follow-ups

  • Open DOI / Open cited URL — eyeball the source
  • Search Scholar / Search web — find near-misses
  • Mark as fabricated — record your judgement
  • Dismiss — struck-through, remembered across re-scans; Restore anytime
Orphans matter both ways: an in-text citation with no bibliography entry may be a missing reference (sloppy) or a citation that never existed (concerning). The tool separates the lists so tutors can apply the appropriate penalty or conversation. Dismiss exists for false positives — e.g. a reference the databases index poorly — and the summary strip updates so "dismissed" items don't inflame the verdict.

Keeping the records — exports

Three buttons on the results screen work over the whole batch:

Export PDF audit-ready

  • One file for all papers: per-paper overview, colour-coded reference table, cross-ref lists
  • Screenshots embedded as thumbnails
  • Date + disclaimer on every page

Export CSV spreadsheet

  • One row per reference: File, Title, Authors, Year, DOI, URL, Status, Confidence, URL Status, Flags, Dismissed
  • Drops straight into Excel/Sheets for moderation panels

Export .bib

  • Verified references only, DOIs included
  • Handy for reading lists and follow-up

Triage travels with the report: rows you dismissed show in the PDF struck-through with a "Dismissed by reviewer" note, and the CSV carries a Dismissed column — the database status stays visible either way.

This is the "keep the receipts" slide for marking moderation and academic-integrity processes: the batch PDF is the artefact to attach to the marking record. Dismissals persist on the tutor's machine (keyed by reference content, so they survive re-runs and app restarts) and appear in exports as a struck-through row plus reviewer note (PDF) or a Dismissed column (CSV) — while the database status pill stays untouched, so the record shows both facts: what the databases said, and what the tutor decided.

Rate limits — what to expect

  • All the databases are free services — CiteSight stays within their polite-pool limits
    • Lookups paced to one request per second (arXiv: one per three seconds)
    • A folder of papers is deliberately slow — slow here means polite
  • Results are cached per run — a work cited in ten papers is looked up once
  • If Semantic Scholar throttles a big batch, that reference shows Unverified with the reason (e.g. "rate-limited on Semantic Scholar")

Unverified ≠ not found. It means "we couldn't ask just now" — hit Re-check (or re-run) to retry those.

Set expectations for the live demo: a 20-paper folder takes minutes, not seconds, and that is by design — the alternative is getting IP-throttled by the free services everyone depends on. The summary strip has a bulk "Re-check N unverified" button for exactly the throttled-batch case.

Key: semanticscholar.org/product/api — free, personal use. The desktop app also reads SEMANTIC_SCHOLAR_API_KEY if you prefer environment variables.

Key etiquette: the key is personal (covers you and your organisation's authorised users). Fine on your own machine; don't put a shared key on a public web server. CiteSight itself ships with no embedded key — everyone brings their own.

Prefer the terminal? There's a CLI

npm install -g cite-sight

cite-sight check ./submissions/              # a whole folder, recursed
cite-sight check "essays/*.pdf"              # or glob patterns
cite-sight check ./submissions/ --json > results.json
cite-sight check essay.pdf --fail-on suspicious   # CI exit codes
  • Same verification engine — folders and globs work; per-file report plus a Batch Summary
  • --json: batch envelope with per-file results + roll-up totals — machine-readable records
  • --fail-on (none | suspicious | broken-url | any) sets exit codes for automated pipelines
  • Same pacing and politeness rules; same --email / --s2-key options

Also available: standalone single-file HTML (no install, runs in your browser tab, document never leaves your device) and Docker for hosting a shared instance.

Keep this to 30 seconds for a tutor audience — the point is "the capability also exists for course teams with scripting needs": point it at a folder like the desktop app, get a batch summary on screen or a JSON envelope for records. The standalone HTML option is worth a one-liner for tutors on locked-down university machines: download one file, double-click, done.

Good to know

  • Free & open data — verifies against Crossref, Semantic Scholar, OpenAlex, arXiv, DataCite, Open Library
  • Private — the app runs on your machine; only reference strings go to the databases for lookup
  • Evidence, not verdicts — Unverified is not Not found; you make the call, the tool keeps the receipts
  • No lock-in — export records as PDF, CSV, or BibTeX; JSON from the CLI
